# Native Hyprland scheduler acceptance

**State:** acceptance procedure only. This document does **not** assert that the checks below have run or passed. It does not authorize switching the production runtime. Track accepted tasks in [scheduler-progress.json](scheduler-progress.json) and [scheduler-migration.md](scheduler-migration.md).

## Rules for the QA operator

- Execute in a real, GPU-backed Hyprland Wayland session. Headless Weston, XWayland and a green hosted CI job are not substitutes. Record the compositor, renderer, display, GPU, backend, Rust build and exact Starbyte commit.
- Use an isolated disposable config and cache. Do not edit the user's live settings or overwrite saves; never commit ROMs, game saves, screenshots from proprietary games or private machine paths.
- Automate the steps and collect logs/screenshots/metrics. Do not hand the operator's keyboard or terminal chores to the user. A real gamepad and audible-speaker checks must be classified **not tested** if no representative device or reliable listening evidence is available.
- The normal player remains the default. Run opt-in worker acceptance with `--native-worker-preview` until every prerequisite is accepted. Do not infer another item's success merely because one check passed.
- A passing synthetic demo proves only that demo and the tested paths; commercial-ROM behavior requires separately obtained local-only evidence.

## Environment receipt

Capture an evidence record *before* launching the application: Git SHA, build mode, `XDG_SESSION_TYPE`, `WAYLAND_DISPLAY`, Hyprland version and monitor/workspace data from `hyprctl -j monitors` / `hyprctl -j workspaces`, GPU/renderer, audio server and device route, connected controller identification (no serial numbers), and the disposable config/cache locations. Record whether the process uses native Wayland. Redact personal filesystem paths before attaching evidence to a public issue.

## Unattended native smoke adjunct (QA operator)

A QA agent with access to the **actual physical Hyprland session** can build the binaries and run the isolated Rust probe collector from this checkout:

```sh
cargo build --locked -p starbyte-egui --bins
target/debug/starbyte-native-qa
```

The helper refuses non-Hyprland sessions, records `hyprctl` monitor/workspace metadata and the working-checkout Git revision, and runs nine existing `--demo --native-worker-preview` original-window smoke modes with isolated HOME and XDG config, data, cache and per-mode logs. A child cannot silently fall back to X11 because its `DISPLAY` is unset, while the real Wayland socket is preserved. It writes `results.tsv` and raw logs in a new private local temporary directory, exits nonzero on any missing success marker or probe error, and performs no changes to the user's normal Starbyte configuration or saves. Run it through the local QA agent rather than handing these terminal steps to the user. Never publish raw logs or environment context before checking them for private paths and machine identifiers.

### Opt-in real-workspace progress probe

On Hyprland versions implementing the current Lua dispatcher interface, a local QA agent can additionally run:

```sh
target/debug/starbyte-native-qa --physical-workspace
```

This adds **two** distinct physical-workspace probes beyond the nine default synthetic cases: one for background play and another for pause-on-blur. After the original window announces the start of a two-second **worker-only callback gap** with a wall-clock timestamp, the operator rejects stale start markers (over 900 ms old), confirms its process is a native (non-XWayland) Hyprland client on the active workspace, switches to a unique empty named workspace using the compositor's dispatcher (within 1,200 ms of the marker), and samples the active workspace periodically for at least 2.25 seconds. It rejects early returns, checks that Starbyte itself remained on the original workspace, and restores the original numeric workspace before checking worker frame-advance and clock-pacing receipts. A local `real-workspace-progress/workspace-transition.json` records the tested process ID, native-client evidence, temporary workspace, observed off-workspace milliseconds and number of compositor samples, confirmed transition and restoration, and explicitly untested audio/gamepad/cutover dimensions without saving other window titles. The original-workspace restoration runs on normal error paths as well. It refuses special/negative original workspaces; on an interrupted or forcibly terminated operator run, explicitly verify the active workspace before continuing. The runner does not turn on this interaction without the `--physical-workspace` option.

The second physical probe first enables pause-on-unfocus in the isolated original-window demo and publishes a timestamped readiness receipt once the worker has warmed up and the window has real keyboard focus. The QA collector then switches workspaces using the same bounded, sampled compositor procedure. On return, the emulation-owner counters must report an actual suspension and later resumption; the frame advance during the away period must stay well below uninterrupted 60.1 FPS, and ten resumed frames must take nonzero wall time rather than arriving as an instantaneous catch-up burst. The saved `workspace-transition.json` records which of the two cases ran. This remains unexecuted physical QA until a local agent runs it; synthetic unit tests and Weston cannot establish that blur was delivered by Hyprland.

A passed opt-in test is useful **actual workspace-transition evidence for independent video clock behavior** but does not prove sound was heard while the game was off-workspace, active gamepad input, real stream recovery, or production cutover. Even for A-08/D-13, the acceptance decision requires review of the physical compositor, timing records and the complete gate wording. The CI contract only validates the runner's code and synthetic markers; it never performs this physical switch.

**Scope limit:** The nine default checks are **synthetic**. Only the separately enabled `--physical-workspace` scenario performs a real workspace transition, and it must actually run on a physical Hyprland host before that evidence exists. Neither mode moves a physical gamepad, verifies speaker audibility, unplugs a device, exercises commercial ROMs, or authorizes production-default cutover. All eight pending hardware/cutover gates remain independently unaccepted until their complete requirements have direct evidence. The helper's own CI compilation and contract-marker tests are not evidence of execution on physical Hyprland.

## Automated native checks

| Gate | Execution | Required observation |
| --- | --- | --- |
| D-12: visible/focused clock | Launch the full original-window shell with `--demo --native-worker-preview` on physical Hyprland; measure the worker-produced frame count against monotonic elapsed time while the app is visible and focused | Stable rate near NTSC 60.1 FPS without recurrent long frame gaps; separately record texture-delivery age, GPU presentation and audio continuity. A fixed 60 Hz monitor is not itself proof of emulation-rate accuracy |
| A-08 / D-13: off-workspace | On a disposable workspace, run with background pause **disabled**, move focus to a different workspace, leave the emulation owner running without egui callbacks, then return | The owner gains approximately elapsed-time × game FPS frames without a burst or permanently held input. Verify video catches up on return and actual background sound is not silently dropped |
| D-14: background pause | Repeat the same workspace transition with pause-on-focus-loss **enabled**, then return | Frames stop while the policy suspends, audio is cleared, and resuming does not simulate the elapsed wall-clock interval in a burst; manual Pause remains independent |
| P-18: sound and device recovery | Use real output routing with game PCM, the shared-worker 440 Hz check, mute/unmute and speed/pitch changes; test a real device disconnect/reselection and restore | Record initial and final audio device state, submitted nonzero PCM, mixer drops/empty observations, CPAL stream-fault count, successful-reopen count and an independent audibility/quality result. Trigger a real disconnect, verify fault count rises, reconnect, verify reopen count rises, then establish audible resumed playback. Opening an OS device or submitting PCM alone cannot establish speaker sound or recovery |
When checking pause/resume and sound on the physical session, switch between 1x and fast-forward while PCM is active and verify frame cadence and pitch/tempo change together, not a transient mixed setting; repeat under concurrent save/cheat activity. For mute, try a volume change while an asynchronous save is busy, then confirm actual sound goes silent and returns on unmute. The source-level saturated-queue regressions in [CI 40118580865](https://github.com/sguzman/starbyte/actions/runs/40118580865) do not replace physical speaker listening or perceptual latency checks.

| P-19 / D-15: interaction and persistence | Exercise original-window menus, all mapped gamepad directions/buttons, cheats, keyboard shortcuts, screenshot capture, F5/F8, disk slots, mode namespace switches and battery SRAM across restart | Before/after evidence for each operation, including correct screenshot pixels, gamepad input press and release at the SNES port, slot contents, surviving save files, and no stale receipt replacing a newer game |

For the physical gamepad portion of P-19/D-15, also rebind a gamepad button or analog/D-pad direction, switch away *without releasing that same physical control*, switch back and verify the captured gesture does **not** move the SNES game until physical release. Verify release restores ordinary new presses, and disconnecting the captured controller clears only its own capture suppression. For the basic focus/backlog checks, press/release mapped face and direction controls while Starbyte is on a *different* Hyprland workspace, return after the UI has been idle for over 500 ms, and confirm no old press edge moves the game on return. Separately, return from a brief blur while egui callbacks continued, and verify there is no stale press edge. For both cases, keep a button or stick direction continuously held over the return and verify it resumes as **held** (not a new press edge); release it and confirm the SNES port clears. Then issue a fresh press with Starbyte focused and confirm it reaches the SNES port and releases correctly. [The queue suppression and held-state resynchronization changes](https://github.com/sguzman/starbyte/commit/f94ae9e799df7590965037d5b526906bfa449800) have only synthetic CI coverage until a real controller and compositor execute that sequence; do not turn this procedure into a passing task without that evidence.
| C-16: production cutover | Only after the above and all other required acceptance checks pass, deliberately switch the default and repeat the entire user-facing regression suite | Old saved settings and saves remain compatible, native background behavior remains correct, and an intentional rollback is documented |

The existing deterministic flags such as `--exit-after-full-worker-no-redraw`, `--exit-after-full-worker-focus-pause`, `--exit-after-full-worker-sram`, `--exit-after-full-worker-shortcuts` and `--exit-after-full-worker-replacement` are useful **automated adjuncts** when launched inside the real Hyprland session. They are *not*, on their own, proof that physically switching workspaces, moving a real gamepad or listening through speakers succeeded. Preserve their distinct success markers and failure logs.

## Audio failure/recovery receipts

The Sound panel exposes separate **OS stream errors** and **reopened after fault** counters (worker or legacy audio, as appropriate). Collect these before and after disconnect/reconnect along with default-output changes and the local audio server’s device state. A positive reopen count measures a newly opened Rodio stream after CPAL reported an error; it does **not** demonstrate physical audibility. An unplug may not generate a CPAL error on every driver/backend: record that as a diagnostic limitation, not a passing recovery test. The original Sound panel also has a manual **Reselect desktop audio output** control for a stale/default-device route: it releases the current Rodio/CPAL stream and allows the next fresh game buffer or in-game speaker check to open the current default output. This manual reset does **not** count as an automatic post-fault recovery, and the enqueue acknowledgement is not proof that a device reopened or that sound was audible. Test the automatic failure path and manual route-reselection path separately, recording actual speaker observations and whether CPAL reported a fault. Never substitute a synthetic callback test for a real disconnect, and do not send private user paths or actual game audio to public artifacts.

## Evidence and decision

For each gate, record `task_id`, `commit`, `time`, `environment`, `setup`, `action`, `observed`, `expected`, `result` (`pass` / `fail` / `not_tested`), and artifact pointers. Attribute native physical evidence and virtual Weston evidence separately. A fail or untested check leaves its checklist item pending. Update both the Markdown task and JSON ledger together only when the gate's direct evidence satisfies its wording; run the ledger parity test in CI. A passing run of unrelated tests cannot increase the accepted percentage.
